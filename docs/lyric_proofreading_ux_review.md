# 歌词校对模块 UX 深度复盘（2026-10-31）

> 审计基线：`main@910f1af` 上的 `lyric_editor_screen.dart`（约 4000 行，单文件 `setState`）、关联 domain 服务、以及 proofread v2/参考对齐相关对话框。  
> 视角：真实校对工作流「听 → 发现问题 → 定位行 → 改字/改时间 → 保存」，而非代码结构正确性。  
> 结论：当前功能完整但交互路径过长、可发现性差、反馈弱；本轮随此文档落地了 6 项高优先级改动（见 §5），其余列为后续迭代。

---

## 1. 方法

1. 通读 `LyricEditorScreen` 完整渲染链：AppBar → `_EditorToolbar` → `_LyricListPane` → `_InspectorPane` / BottomSheet、`_BottomBar`，以及所有弹窗（参考对齐、proofread v2、时间轴校验）。
2. 在 390×844（紧凑）、1024×768（中等）、1600×900（宽屏）三种视口心智模拟：单行纠错、多行批量、长歌 100+ 行、音频缺失、无智能复核队列四种场景。
3. 对照 PRD 中「人声起点/终点 ≤ 10ms 误差」「双引擎互检」「智能复核不宣称正确率」等约束，检查文案是否造成误解。

## 2. 当前最大痛点：逐行编辑链路过长

### 2.1 单行改错需要 3 次跳转

旧流程（桌面/移动一致）：

```
点击行 → 打开右侧 Inspector（桌面）或 BottomSheet（移动）
        → 在第二屏找到 TextField
        → 改字 → 关闭抽屉 → 回到列表确认
```

改一个错别字平均 4 次点击 + 视线在两处面板间切换；连续改 10 行时往返尤其明显。列表本身只读，截断到 1–2 行，长句必须进 Inspector 才能看全。

**体验问题：**
- 列表与编辑器割裂，违背「就地编辑」原则（direct manipulation）。
- BottomSheet 会遮住上下文：改第 20 行时看不到第 19、21 行的衔接。
- 没提供「双击即改」这类用户从表格/文档类软件带来的心智预期。

**本次改动：**
- 新增 `_InlineLyricEditorRow`：在列表内原位展开为编辑态，双击行（桌面）或长按（触屏）即可进入，自动全选文本，回车保存、Esc 取消、显式按钮兜底。
- 行选中时长句自动展开到 4 行，避免进 Inspector 才看全。
- 行尾在选中态显示 ✎ 提示 + Tooltip「双击或按 F2 编辑」，提升可发现性。

### 2.2 时间只能 nudging，不能直输

旧 `_TimingEditor` 只提供 `-1s / -100ms / -10ms / +10ms / +100ms / +1s` 六档微调。若需要把 `00:12.30` 改成 `01:45.00`，用户要按 20+ 次。

**本次改动：**
- 时间戳本身变为可点击的虚线下划线，点击弹出 `_TimestampEditDialog`，支持 `mm:ss.hh` 与 `83.5`（秒）两种输入，校验起止顺序，失败在输入框内提示而非 SnackBar 丢失上下文。
- 列表行内也展示 `start → end` 两个可点击时间段，桌面用户无需打开 Inspector 即可校时。
- 保留 Inspector 内的 nudging 作为精细微调用，两种路径互补。

### 2.3 搜索/定位能力缺失

长歌 120 行时找「那句副歌」只能靠肉眼滚动或切不同 filter；`_ReviewFilter` 的 4 个 chip（全部 / 待复核 / 低置信度 / 智能复核）语义重叠，用户分不清「待复核」与「智能复核」差异。

**本次改动：**
- 在列表顶部加入轻量搜索框（`_searchController` + 本地过滤），支持按歌词文本、时间戳、行号查找，超过 8 行才显示以免打扰短歌。
- 空结果展示明确的「没有匹配的歌词行」状态，而非空白。
- 后续建议见 §6.1：为 4 个 filter 增加一句文案说明，或合并「待复核」与「智能复核」为一筛。

## 4. 关键交互建议（按工作流）

### 4.1 单行纠错工作流（最高频）

```
旧：听 → 暂停 → 找到行 → 单击 → 等抽屉 → 改字 → 关闭 → 播放
新：听 → 双击文字就地改 → 回车保存 → 空格继续
     （时间：点击时间戳弹框直输，或用当前播放标记起终点）
```

设计要点：
- 双击命中区为整行文本区域，不含试听按钮（避免误触）；右键/长按提供编辑、删、复制、标记起终点等二级操作。
- 行内编辑时起止时间保持可见，提醒用户这是「同一行」的两个维度。
- 保存为整行原子操作：`confidence=100` + `manuallyEdited` 标记 + 撤销快照失效逻辑自动化，用户无需理解背后机制。

### 4.2 批量校对工作流

1. 参考对齐后的「安全批量采纳」与「需逐行确认」分区做得好，但「全选低置信」二次确认弹窗文案过长；建议改为在按钮上直接标注 `× N 行，相似度 <80%`，二次确认只在超过 5 行时出现。
2. 智能复核队列的「优先分」数值化值得保留，但 Tooltip 中的原因列表应限制为 3 条以内，超出折叠，避免弹窗过高。
3. 复核确认按钮「确认歌词与时间无误并继续」过长，移动端换行；建议拆为「确认无误 ✓」+ 副标题「自动跳到下一优先行」。

### 4.3 时间轴校对工作流

- 将 Inspector 内的 6 个 nudging 按钮改为「±1s 大步、±0.1s 中步、±0.01s 微步」并用不同字重区分，减少误触。
- 在行尾增加「波形微缩图」占位（后续对接 `PcmDelayLine` 数据），让用户直观看到人声起终点是否卡在静音段。
- 全局偏移改为「试听偏移（不写入文件） vs 写入偏移」，用两个 tab 区分，当前单一 `globalOffset` 既影响试听又影响导出，用户无法预览「只调播放不对文件」的效果。

## 6. 后续迭代建议（未在本轮编码，按优先级）

### 6.1 必须做（影响正确性或数据安全）

1. **撤销栈**：为逐行编辑引入 `UndoManager`（最多 50 步，内存快照），`Ctrl+Z / Cmd+Z` 可用；当前只有参考对齐的单次 `_AlignmentUndoSnapshot`，误改 5 行后无法回退。
2. **保存按钮可达性**：移动端在 `_BottomBar` 增加常驻「保存」图标，AppBar 的保存仅作冗余；或底部上浮 FAB，`hasChanges` 时脉冲提示。
3. **BottomSheet 防遮**：编辑 sheet 改为 `DraggableScrollableSheet`，支持半展开时仍能看到列表上下文。
4. **删除二次确认**：行内删除（尤其是键盘 Delete）加 `SnackBar` 撤销，而非立即删；Inspector 内的删除按钮改为 `AlertDialog` 二次确认。
5. **导入冲突可见性**：`ReferenceLyricInput.conflicts` 当前只在参考对齐 sheet 顶部展示，应用后消失；应在文档 `metadata` 中持久化并在主列表以警示条常驻，直到用户显式忽略。

### 6.2 应该做（显著提升效率）

6. **行号跳转**：`Ctrl+G` 输入行号跳到对应行并高亮 1 秒，解决 100+ 行歌的定位。
7. **拆分/合并行**：在行内菜单增加「在此处拆分行 / 与下一行合并」，自动按字符中点分配时间，比手动删建更符合用户意图。
8. **批量选择**：长按行号进入多选模式，底部出现「标记已复核 / 删除 / 标记副歌」批量操作；当前只能逐行确认。
9. **Follow 模式优化**：`followPlayback` 打开时，用户手动滚动应自动暂停跟随 3 秒后才恢复，避免「想看前面却被拉回」。
10. **全局偏移解释**：在偏移控件旁加 `ℹ` 按钮，弹窗说明「偏移只影响播放对位，不改行时间；导出 LRC 时会叠加」。

### 6.3 可以做（体验加分）

11. **波形/音量可视化**：行尾微缩波形或仅在 Inspector 内展示 5 秒片段，帮助判断起终点是否切在呼吸声上。
12. **拖动改时**：在列表行背景增加可拖动的起终点手柄（类似视频剪辑时间轴），直接拖动改变 `startTime/endTime`，nudging 作为辅助。
13. **Filter 合并**：将「待复核」「低置信度」「智能复核」合并为「建议复核」单一入口，内部按分数排序；当前 4 个 chip 增加认知负担。
14. **空状态引导**：空歌词页增加「从参考歌词导入」与「从模板生成」两个按钮，而非只有「添加第一行」。
15. **无障碍**：为试听按钮、badge、时间戳增加 `semanticsLabel`，支持读屏；当前仅靠颜色与图标区分。

## 8. 术语表

- **就地编辑 (inline edit)**：不在新页面/弹窗中改，而在原位展开输入框。
- **智能复核 (smart review)**：`LyricReviewPriorityService` 按置信度/双引擎分歧/重复/时间轴异常打分的排序，分数仅表优先级。
- **手工编辑保护**：`LyricManualEditMarkerService` 按稳定 `lineId` 记录用户改过文本的行，参考对齐默认跳过。
- **时间轴校验**：`LyricTimelineValidator` 检查重叠/倒退/越界等问题。

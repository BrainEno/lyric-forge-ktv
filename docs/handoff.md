# Handoff

## 目标

审计路线的第二十五轮（第二十四轮 PR #496 已合并为 `e763e62`）。用户要求“接着做下一轮”，按第 24 轮报告的建议：“有人声没歌词”的段落可以一次全部识别，最后一次确认插入。要求有效代码量不少于 1000 行，PR 过 CI 后直接合并。

1. 全部识别（D-046）：
   - `LyricVocalGapBatch` 为每处空白段规划识别范围（同 D-045），并把选中的结果在原文档上一次插入：副引擎证据只重新对应一次，同一对相邻行之间的两处结果互不重叠，可以在同一次修改里把没有结果的段标记为“这里没有歌词”；
   - `LyricVocalGapBatchDialog` 打开后依次识别每一处，所选引擎识别不出或出错时自动换另一个引擎再试一次；运行时正忙或停止时结束这一轮、保留已有结果，可以“再识别没有结果的 N 处”；每处一个勾选框，可试听。
2. 入口：识别摘要卡在有两处及以上空白段时显示“全部识别（N 处）”。
3. `LyricVocalCheckActions.toDocumentTimeline` 统一把识别结果从音频时间轴换到文档时间轴，单段对话框也改用它。
4. 文档：D-046、`high_quality_asr.md`、工作日志。

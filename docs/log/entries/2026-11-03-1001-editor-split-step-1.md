# [2026-11-03 10:01] Take the first slice out of the 4,591-line lyric editor

- Scope: Phase 4 item 4.1, first step. `LyricEditorScreen` was 4,591 lines with **zero widget tests**: every rule lived inside a 2,067-line `State`, so the only way to check a behaviour was to drive the whole editor — services, project repository, playback session and all. This step splits off the two halves that can be separated without touching the proofreading orchestration: the line-audition state machine, and the presentational panes.
- Files: `lib/features/lyrics/presentation/controllers/line_audition_controller.dart` (new), `lib/features/lyrics/presentation/widgets/lyric_list_pane.dart` (new, moved), `lib/features/lyrics/presentation/widgets/lyric_inspector_pane.dart` (new, moved), `lib/features/lyrics/presentation/widgets/lyric_editor_atoms.dart` (new, moved), `lib/features/lyrics/presentation/screens/lyric_editor_screen.dart` (4,591 → 2,597 lines), `lib/features/lyrics/domain/models/lyric_review_queue.dart` (shared threshold constant), `test/features/lyrics/presentation/controllers/line_audition_controller_test.dart` (new, 13 cases), `test/features/lyrics/presentation/widgets/lyric_list_pane_test.dart` (new, 5 cases), `docs/reviews/2026-10-31-recognition-quality-and-ux-deep-review.md` (§4.1 progress note, plan row), `docs/log/entries/2026-11-03-1001-editor-split-step-1.md`, `docs/handoff.md`, `docs/work_log.md`, `docs/work_log_archive.md`, `docs/work_log_index.md`.

- Notes: The extraction was deliberately behaviour-preserving — the panes' parameter lists are unchanged, so what moved is a move, not a rewrite. Two decisions were not mechanical. First, the audition rules moved into a controller that talks to `AudioPlayerService`/`PlaybackSessionService` and takes the "load this project" step as a callback, because the queue item needs the project manifest that only the screen has; that keeps the controller's tests free of the repository and of Flutter. Second, the duplicated confidence threshold: the editor carried its own `_reviewConfidenceThreshold = 70` while `LyricReviewQueue` carried the same number as a default, so the inspector and the queue could have drifted apart — both now read `kLyricReviewConfidenceThreshold`. What is left in the screen is still the expensive part: the proofreading orchestration (~600 lines: strategy selection, pipeline calls, proposal commit) and the document editing/undo/save flow. Those are the next controller, but they are tangled with dialogs and `ServiceLocator`, so they deserve their own round rather than more mechanical lifting. Widget-test gotcha worth remembering: a row with `onDoubleTap` resolves a single tap only after the double-tap timeout, so a tap test must pump ~400 ms before asserting.

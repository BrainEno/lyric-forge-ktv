# [2026-10-31 01:35] Supervise high-quality shared audio preparation

- Scope: Close the remaining ASR process-lifecycle gap called out in `docs/engineering_risks_roadmap.md` (Priority 2): the high-quality route's shared 16 kHz normalization FFmpeg run used a bare `Process.start` with an unbounded `exitCode` wait and unbounded stderr collection, unlike the Whisper/Qwen/chunk paths supervised by PRs #211, #212, and #214. `HighQualityTranscriptionService._prepareSharedAudio` now runs FFmpeg through `AsrProcessSupervisor` with the source-size-aware budget from `AsrProcessTimeoutPolicy.ffmpegPreprocessingForFile`, bounded diagnostic tails, timeout mapped to an environment failure, and supervisor-based termination (with escalation) from `cancel()`/`dispose()`. This ports the semantics of the stranded branch `fix/supervise-high-quality-audio-preparation-20261028` onto current main; that branch's resumable-chunk edits are deliberately not ported because PR #214 already supervises that service, and its work-log deletion is not reproduced.
- Files: `lib/features/transcription/data/services/high_quality_transcription_service.dart`, `test/high_quality_transcription_service_test.dart`, and this work-log entry plus generated navigation.
- Validation: Added fake-process tests proving that (a) a normalization timeout surfaces as a `TranscriptionFailureKind.environment` failure, terminates the child, and removes the partial shared WAV, and (b) cancelling mid-normalization escalates from SIGTERM to SIGKILL, reports cancellation, and removes the partial WAV without invoking either engine. The timeout is injectable via the new optional `sharedAudioTimeoutForFile` constructor parameter (defaulting to the shared policy), and `processSupervisor` can be injected like in the Whisper service. Local Flutter/Dart SDKs are unavailable here; the final PR head must pass the Flutter Quality Gate before merge.

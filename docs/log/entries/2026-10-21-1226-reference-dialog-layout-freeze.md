# [2026-10-21 12:26] 修复参考歌词对话框内 LayoutBuilder 导致的卡死

- Scope: 修复“点击参考歌词纠正后界面卡死、终端刷 `'!_debugDuringDeviceUpdate': is not true`”的问题。根因是 `reference_alignment_dialog.dart` 的 `AlertDialog.content` 子树里放了 `LayoutBuilder`：`AlertDialog` 用 `IntrinsicWidth` 量算内容宽度，`LayoutBuilder` 不支持返回固有尺寸，布局阶段抛 `LayoutBuilder does not support returning intrinsic dimensions`，该异常中断对话框布局，使 overlay 里的渲染盒停留在 `size: MISSING`；随后鼠标的 hit-test 抛 `Cannot hit test a render box with no size`，而这次异常发生在 `MouseTracker._deviceUpdatePhase` 的分发回调里，`_debugDuringDeviceUpdate` 因异常未复位而永久为 true，之后每个鼠标事件都断言失败（鼠标失效、界面看似卡死）。改成不使用 `LayoutBuilder`：按视口宽度与对话框 inset/padding 估算内容宽度，再决定两个溯源输入框横向并排还是纵向堆叠。
- Files: 修改 `lib/features/lyrics/presentation/widgets/reference_alignment_dialog.dart`（移除 `LayoutBuilder`；`build` 内按 `media.size.width`、`spec.pageGutter`、`maxWidth` 估算 `contentWidth` 并得出 `stackMetadataFields`，字段实例提到 `build` 顶部复用）；新增 `test/features/lyrics/presentation/widgets/reference_alignment_dialog_test.dart`（2 例：390 宽纵向堆叠 + 打开与鼠标悬停零异常；1366 宽横向并排）。
- Validation: 临时复现测试（已删除）先用鼠标完整走通“悬停按钮 → 打开对话框 → 粘贴 → 开始对齐 → 逐行确认 → 应用 → SnackBar”，修复前首个异常正是 `LayoutBuilder does not support returning intrinsic dimensions`（`AlertDialog`），修复后同一流程 0 异常；`dart format` 两个改动文件；`flutter test --no-pub test/features/lyrics/presentation/widgets` → 14/14 通过（含新增 2 例）；`flutter analyze --no-pub`（全项目）→ No issues found。
- Notes: 环境限制：`flutter test` 默认不是桌面鼠标设备，因此回归测试用 `createGesture(kind: PointerDeviceKind.mouse)` 复刻鼠标路径；真实 Windows 窗口未人工点击复核，建议手工确认“参考歌名/参考艺术家”在 390/1366 宽下分别为堆叠/并排且可正常输入。宽度判断用估算而非实测（对话框宽度 = `min(视口宽 - 2×pageGutter, maxWidth)`），与原先 460 阈值行为一致；`lyric_editor_screen.dart` 仍只格式化新增行，未整文件重排。

# [2026-11-01 18:20] Stop the upload timeout test racing the teardown it is waiting for

- Scope: CI hygiene. Merging the fusion fix turned `main` red within four minutes even though the pull-request gate had just passed on the identical tree (`3d53a4e` versus merge commit `f54f292`, `git diff` empty). The repository gate is therefore not reproducible run to run, and a red `main` currently means "a test raced itself" rather than "the product is broken". Hunting with repeated gate runs caught the culprit: `test/features/transfer/http_media_hub_upload_test.dart`, `total upload deadline applies while chunks continue arriving`, failed 5 times in 30 runs and once in 8 earlier gate runs. Root cause was in the test, not the hub: it kept writing request body bytes until the *entire* response had been read, but the hub answers at the total deadline and closes the connection immediately, so the client sometimes observes the close before its reader sees the buffered response. The next `socket.write` then threw `StateError: Cannot add event after closing`, which the loop's `SocketException` and `TlsException` handlers did not cover, so it escaped as an unhandled test failure. Writing into a socket the server already closed can also reset the connection and discard a response that did arrive. The test now reads through `_RawResponseReader`, which reports the first response byte, stops writing the moment an answer starts, treats a peer-initiated close during the write as the expected end of the probe, and tolerates a reset after the first byte while still failing if the connection dies before any response byte.

- Notes: Two behaviour changes, both consequences of removing a fallback. First, the two player bars are not rendered before `AppServices.initialize()` has run: they used to read `late final` services in `initState`, which throws when the shell is built without bootstrap, and the shell now simply has no bundle to give them. Production always initialises first, and the app shell already skipped the lyric-sync widget for the same reason. Second, `PlaybackQueuePanel` gained a required `collectionRepository` because its "save queue as playlist" was the last place that resolved the repository itself; `NowPlayingDependencies` therefore carries one extra field, which is honest — that button genuinely needs it. Design note: the library gets **one** bundle rather than four per-screen objects. Unlike the playback surfaces (whose dependency objects differ per screen because each uses a different subset), the five library sections are one screen with five bodies and share almost the whole set; splitting them would have produced four near-identical classes. `LyricsImportDependencies` is separate because it travels to three unrelated call sites (library, quick play, both bars) through widget callbacks. The formatter again flattened historical format debt in `playback_queue_panel.dart` (~69 lines) — the same one-time cost documented for `project_detail_screen.dart`, and not a rewrite.

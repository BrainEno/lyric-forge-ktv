# [2026-11-01 17:00] Stop fusion from duplicating lyrics across mismatched segmentation

- Scope: Phase 1 item 1.2 of the recognition-quality roadmap, and a correction of the roadmap's own R2 finding. Measuring the real service showed the previous write-up was wrong in both directions: the dual-engine merge does not duplicate every unmatched secondary row (the contained-fragment path suppresses most of them), but it does inflate the document when the two engines segment at very different granularity. The cause is `_containedFragmentMatchesTimeline`, which predicts where a fragment should sit by mapping its character offset onto the parent line's duration. Singers do not pace text linearly and ASR timestamps carry hundreds of milliseconds of jitter, so genuine fragments fail that estimate and are inserted as extra rows. A fragment whose text is already inside the parent line and whose span is inside the parent's span is now treated as the same lyric. Separately, the Phase 0 duplicate metric could not see these rows at all: it compared start times only, so a fragment starting three seconds into a twelve-second parent was invisible. It now also treats span nesting as evidence of coincidence.

- Notes: The fix deliberately prefers dropping a nested repeat over keeping a duplicate row: if a backing vocal restates words inside a span the primary already covers, those words are still present in the document, only without a separate timestamp. The proportional estimate is retained for fragments that stick out of the parent span, which is a real boundary disagreement and stays as a review row. Two guard tests protect the fix from being "solved" by discarding all secondary output: one asserts a genuinely new ad-lib line still survives at confidence 60, the other asserts the row count equals the authoritative engine's row count. The test that previously asserted the defect as expected output now expects only the novel line. Not fixed here: whichever engine is authoritative still dictates global segmentation, so a finer-grained Qwen primary yields its own 40-row split; that belongs to R1/R7. No corpus numbers are claimed; the synthetic fixtures isolate the merge step and say nothing about real songs.

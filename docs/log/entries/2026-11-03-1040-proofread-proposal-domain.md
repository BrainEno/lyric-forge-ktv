# [2026-11-03 10:40] Move the proofread proposal logic out of the editor widget

- Scope: Phase 4 item 4.1, second step. The first step lifted the audition state machine and the three panes; what remained in `_LyricEditorScreenState` was the proofreading flow, which mixed four unrelated jobs in one 358-line method: parse the optional second transcript, run a pipeline, translate pipeline output into review rows, and turn the user's ticks back into a document. The last two are pure data work that could only be verified by driving the whole editor. They now live in `domain/proofreading/`.
- Files: `lib/features/lyrics/domain/proofreading/proofread_review_proposal.dart` (new), `proofread_v2_review_assembler.dart` (new), `proofread_v2_document_composer.dart` (new), `forced_alignment_language.dart` (new), `lib/features/lyrics/presentation/widgets/lyric_proofread_v2_dialog.dart` (review types moved out), `lib/features/lyrics/presentation/screens/lyric_editor_screen.dart` (2,597 → 2,298 lines), `lib/features/transcription/domain/services/asr_runtime_manager.dart` (`hasReadyComponents`), `test/features/lyrics/domain/proofreading/proofread_v2_review_assembler_test.dart` (new, 16 cases), `proofread_v2_document_composer_test.dart` (new, 14 cases), `forced_alignment_language_test.dart` (new, 4 cases), `test/asr_runtime_status_test.dart` (+2 cases), `test/features/lyrics/presentation/widgets/lyric_proofread_v2_dialog_test.dart` (import), `docs/reviews/2026-10-31-recognition-quality-and-ux-deep-review.md`, `docs/log/entries/2026-11-03-1040-proofread-proposal-domain.md`, `docs/handoff.md`, `docs/work_log.md`, `docs/work_log_archive.md`, `docs/work_log_index.md`.

  - `proofread_v2_review_assembler_test.dart` builds real pipeline output (`ReferenceFirstPipeline`, `AsrFirstPipeline`) instead of hand-made fixtures, using the draft/reference pair that forces one interpolated reference line (no draft source) and one unmatched draft row — so the test proves review rows follow reference order, that a source-less row stays amber with its interpolation reason, that a dropped row stays visible for restore, that coverage is only explained when the strategy was automatic, and that the Chinese wording names which evidence was missing.
  - `proofread_v2_document_composer_test.dart` covers what the widget used to own: accept replaces in place, unaccepted keeps the draft, locked applies unconditionally, a source-less proposal is appended in review order, a dropped line comes back only on restore and is re-inserted by timestamp rather than review order, reference-first timing edits reset the global offset while text-only and ASR-first edits keep it, timing provenance follows only surviving line ids, and missing ids get assigned.
  - `forced_alignment_language_test.dart` covers the Chinese/English names, BCP-47 tags, whitespace/casing, and that an unsupported language throws instead of silently defaulting.
- Notes: Two things were not a pure move. First, the review row types (`LyricProofreadReviewVerdict`, `LyricProofreadV2ReviewItem`, `LyricProofreadV2DroppedItem`, `LyricProofreadV2Selection`) lived in the dialog widget file, which made them unusable from domain — the layering ratchet forbids domain → presentation. Moving them into domain was the prerequisite for the other two files. Second, `ForcedAligner` readiness had a real defect: the screen asked for `qwenRuntime` + `qwenAligner` by scanning `components`, while `AsrRuntimeStatus.isBaselineReady` deliberately treats an absent component as "this profile does not need it" (existing test relies on that). The two meanings were conflated; a component that was never inspected would count as ready. `hasReadyComponents(Set)` now requires each requested component to be reported *and* ready, and the baseline getter keeps its old semantics — the difference is documented on the new method. Still not extracted: document editing/undo/save (the remaining object for `LyricEditorController`) and the forced-alignment runner wiring, which needs `ServiceLocator`.

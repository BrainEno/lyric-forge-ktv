# [2026-11-25 11:20] Group the lyric editor inputs

- Scope: UI/UX audit E-04. `LyricEditorContent` took 50 constructor arguments (44 at audit time) and the lyric editor screen built it in one 110-line call where undo, proofreading tools, row edits and audition settings were interleaved, so a new tool meant threading a callback through three places and reading past dozens of unrelated ones. Thirty-one of them now travel in four immutable groups in `lyric_editor_actions.dart`: `LyricUndoRedoControls` (undo/redo, availability and labels, with `undoOrNull` and `availableUndoLabel` replacing the inline `canUndo ? … : null` checks), `LyricProofreadActions` (reference alignment and its follow-ups, proofread, script unification, batch text tools; `none` when nothing applies, and `forDocument`, which now owns the availability rules the screen used to spell out inline), `LyricLineEditActions` (add, insert, update, delete, split, merge, offset, start/end from playback) and `LyricAuditionControls` (preview, active row, playing, loop). The content takes 23 arguments. The screen builds the groups at the call site (`LyricProofreadActions.forDocument`, `_lineEditActions`, `LyricAuditionControls` with `_setLoopCurrentLine`), with the same availability rules as before (alignment follow-ups stay available without lyrics), and stays under the 1,200-line budget of `lyric_editor_orchestration_contract_test.dart` (1,189 lines). The undo group is not called `LyricEditHistory` because the domain already has a class of that name.

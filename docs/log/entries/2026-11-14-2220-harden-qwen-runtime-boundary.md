# [2026-11-14 22:20] Harden the local Qwen runtime security boundary

- Scope: Fix #415. Before this change, the local `qwen3-asr serve` runtime accepted unauthenticated `/v1/transcribe` and `/v1/align` calls that read arbitrary file paths. LyricForge also reserved a port, released it and let the runtime rebind it, then trusted any `200` from `/healthz`. The managed runtime now runs in `--lyricforge-session-stdin` mode (new Rust patch `qwen3-asr-session-auth.patch`, runtime `asr-runtime-v3`). LyricForge writes a fresh 256-bit secret to the child's stdin. The runtime binds `127.0.0.1:0` itself, with `SO_EXCLUSIVEADDRUSE` on Windows, and announces the port with an HMAC proof on stdout. Every route, including `/healthz` and OPTIONS, requires an HMAC-SHA256 request signature with timestamp and nonce replay checks. Every response is signed, the permissive CORS layer is removed, and the runtime exits on stdin EOF. On the Dart side, `QwenRuntimeLauncher`/`QwenRuntimeSession` replace the port reservation and the unauthenticated health polling in both the transcription service and the managed installer. Requests are signed before a socket is opened, and unproven responses are discarded and stop the runtime. The secret is zeroed on close, crash, cancel, idle shutdown, config change and dispose.

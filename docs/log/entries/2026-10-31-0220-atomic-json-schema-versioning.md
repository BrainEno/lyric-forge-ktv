# [2026-10-31 02:20] Add per-store schema versioning to atomic JSON persistence

- Scope: Continue issue #221 by formalizing per-store schema versions for every `AtomicJsonFile` document. Inventory showed the stores already wrote an ad-hoc `version` field (library at 3, batch queue at 2, most others at 1) that only the playback session store ever read. `AtomicJsonFile` now adopts that existing `version` key as the canonical stamp (avoiding a second competing key) and provides `schemaVersionOf`, `stampSchemaVersion`, and a `versioned` validator combinator: unstamped legacy documents count as version 0 and stay readable so they can be restamped on the next write, malformed stamps are rejected as corrupt, and documents stamped by a newer app version are rejected so an older build routes them into the existing recovery / refuse-to-overwrite paths instead of silently rewriting data it does not understand. All ten stores declare a `_schemaVersion`, validate through the combinator, and stamp outgoing payloads; the playback session store drops its bespoke `version == 1` checks in favor of the shared gate. No payload shapes changed, so the legacy-to-current step is the identity for every store today; future shape changes bump a store's version and migrate on load via `schemaVersionOf`.
- Files: `lib/core/persistence/atomic_json_file.dart`; the ten stores under `lib/features/{player,project,transcription,transfer}/data/` that use it; `test/core/persistence/atomic_json_file_test.dart` (schema stamp parsing, stamping copy semantics, validator gating, refuse-to-overwrite of newer documents, backup fallback on downgrade, legacy writability); `test/features/player/playback_session_schema_version_test.dart` (legacy unstamped session loads, newer-schema session is rejected untouched; kept out of the pre-tall-format persistence test file so this change does not drag in its unrelated whole-file reformat); and this work-log entry plus generated navigation.
- Validation: Local Flutter/Dart SDKs are unavailable here, so this was written against the existing store patterns and must be proven by CI: the final PR head must pass the Flutter Quality Gate (format, analyze, the targeted persistence/session tests, work-log preflight), the macOS and Windows persistence legs, and the remaining contract checks before merge. The work-log replica lint reports 0 errors (4 pre-existing commit-subject warnings from the squashed PR #256 remain, which are warning-only by design).
- Notes: This does not close issue #221: real process-kill/power-loss injection beyond the deterministic stage hooks is still outstanding, and the Windows delete/rename window keeps its startup-recovery fallback. Downgrade semantics are deliberate — a build facing a newer-schema canonical document falls back to the newest backup it can read rather than destroying the newer data, and refuses to overwrite when no readable copy exists. Eleven other JSON file writers that do not use `AtomicJsonFile` (take-history, transcription settings, managed-runtime manifests, and similar sidecars) were left out of scope; they can adopt the same helpers later if their durability requirements grow.

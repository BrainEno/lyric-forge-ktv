# [2026-11-02 10:31] One review queue instead of three review numbers

- Scope: Phase 3 item 3.3 (review §4.4, continuing R8). The editor showed three review numbers side by side — `低置信度 N`, `待复核 N`, `智能复核 N` — and drove three filters from three different computations. R8 stopped the worst of it by making unscored lines stop counting as low confidence, but the structural problem remained: "needs review" had three implementations, so the numbers could disagree with each other, and a document transcribed by an engine that returns no probabilities still had no honest way to say "we do not know". The goal here was one concept, one count, one filter set — and a vocabulary that distinguishes "the engine was unsure" from "the engine never scored this".
- Files: `lib/features/lyrics/domain/models/lyric_review_queue.dart` (new: the queue plus every derived count, built once and shared), `lib/features/lyrics/presentation/widgets/lyric_editor_toolbar.dart` (one number in the status line, `未评分 N` as information, filter menu reduced to 全部 / 待复核 / 低置信度 with the last one disabled and explained when nothing was scored), `lib/features/lyrics/presentation/screens/lyric_editor_screen.dart` (the ad-hoc `_needsReview` predicate and the two hand-rolled counts are gone; filters and row badges read the queue), `test/features/lyrics/domain/models/lyric_review_queue_test.dart` (new, 9 cases), `test/features/lyrics/presentation/widgets/lyric_editor_toolbar_test.dart` (updated to the new vocabulary), `docs/reviews/2026-10-31-recognition-quality-and-ux-deep-review.md` (§4.4, plan table), `docs/log/entries/2026-11-02-1031-single-review-queue.md`, `docs/handoff.md`, `docs/work_log.md`, `docs/work_log_archive.md`, `docs/work_log_index.md`.

- Notes: The acceptance criterion in the review ("正确转写时告警数为 0") is what drove the design: a clean document now shows `待复核 0` whether or not the engine scored it, because the queue only contains lines with actual evidence (empty text, engine disagreement, timeline anomaly, repetition, odd duration, or a real low score). Two deliberate choices: the 低置信度 filter stays visible but disabled when nothing is scored rather than disappearing (same rule as the toolbar overflow menu — an unavailable action explains itself), and row badges now show queue state only, with the raw score and 未评分 moved to the inspector, so a single row is never judged by two different standards. The remaining gap is unchanged and recorded in the review: this is an ordering signal built from structure, not a claim about whether the words are right.

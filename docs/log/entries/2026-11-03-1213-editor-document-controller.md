# [2026-11-03 12:13] Move the editing session out of the lyric editor widget

- Scope: Phase 4 item 4.1, third step. After the first two steps the editor was 2,298 lines and the remaining untested half was the editing session itself: six fields (`_editingDocument`, `_hasChanges`, `_selectedLineIndex`, `_manuallyEditedLineIds`, `_alignmentUndoSnapshot`, `_editHistory`) mutated from twenty-odd places, with the rules encoded in whichever `setState` block happened to run first. `LyricEditorDocumentController` now owns all six, and the screen reads them through three getters.
- Files: `lib/features/lyrics/presentation/controllers/lyric_editor_document_controller.dart` (new: `LyricEditorDocumentController`, `LyricEditorSnapshot`, `LyricEditResult`), `lib/features/lyrics/presentation/screens/lyric_editor_screen.dart` (2,298 → 2,064 lines; `_AlignmentUndoSnapshot`, `_recordEdit`, `_clearIndexedReviewMetadata` and the inline bodies of add/insert/update/delete/offset/undo/redo/restore are gone), `test/features/lyrics/presentation/controllers/lyric_editor_document_controller_test.dart` (new, 43 cases), `docs/reviews/2026-10-31-recognition-quality-and-ux-deep-review.md`, `docs/log/entries/2026-11-03-1213-editor-document-controller.md`, `docs/handoff.md`, `docs/work_log.md`, `docs/work_log_archive.md`, `docs/work_log_index.md`.
- Validation:
  - Temporary CI workflow on the pinned toolchain (Flutter 3.47.7 / Dart 3.13.5): `dart format` on changed files, `flutter analyze --no-pub --no-fatal-infos lib test` clean, the controller + audition + edit-history + layering tests green, and the full `scripts/quality_gate.sh --skip-pub-get` green on the first attempt (run 41576455387). The workflow is deleted before the pull request.
  - The 43 cases are the rules that used to be implicit: only a text change marks a row as manually edited (a timestamp nudge does not); deleting a row drops its mark; selection after a delete clamps or shifts with the row that replaced it; typing in one row merges into one undo step but different rows do not; undo never restores a selection that no longer exists; undo/redo round-trip a whole editing session; a new edit drops the redo branch; loading a project clears history and restores persisted protected ids; row-indexed fallback metadata is dropped on insert/delete; add/insert place rows and assign ids; the global offset merges into one step; review marking is undoable; a batch change (alignment/proofreading) is undoable as a unit and any ordinary edit invalidates it; restoring the alignment backup keeps only surviving marks; saving persists this session's marks.
- Notes: Two decisions are worth keeping. First, the audition coupling was inverted rather than moved: the controller does not know about auditions, it only answers "does this edit clear the audition?" (`LyricEditResult.clearsAudition`), and the screen answers "is this row the one playing?" with `_isAuditionTarget`, which keeps the old rule exactly — a *timing* change to the auditioned row drops the highlight, a text change does not. Second, `setLineReviewed` gained a real no-op check: the decision service returns a fresh document (new timestamp) even when the row is already in the requested state, so `identical()` never caught it and re-marking a row became a phantom undo step. That is the one intentional behavior change in this step. Deliberately not moved: the review queue, the filter, the follow-playback toggle and focus requests stay in the screen, because they are view state derived from the document rather than part of it. Phase 4.2 (assembly layer and `ServiceLocatorGlobal`) is untouched.

# [2026-11-03 00:43] One persistent navigation for the whole app

- Scope: Phase 3 item 3.5 (review §4.1). The app was three worlds wired together by buttons on the dashboard: the music library, the KTV/proofreading flow, and eight device-transfer screens. There was no persistent way to say "take me back", so the only route home was the back stack — which after an import could be six screens deep and pointed at the wrong place anyway. A user opening the app for the first time had nothing to learn the shape of it from.

- Notes: Three decisions carried the design. First, the shell lives in `MaterialApp.builder`, outside the navigator, because per-screen navigation cannot know where the user came from; that also meant adding a `navigatorKey`, since `Navigator.of` finds nothing from above the navigator. Second, 工程 is the root route and the other three are pushed on top of it, so back returns to the previous place instead of exiting the app. Third, the library's own `NavigationRail`/`NavigationBar` had to go: with the global shell they stacked (rail inside a rail on desktop, bar under bar on mobile) and 设置 appeared twice — its five sections became a strip at the top of the content instead. Two things were deliberately not done: device transfer did not become a destination (it is a flow, not a place), and there is no nested navigator per destination (that would complicate Android back semantics for little gain). Implementation notes for whoever touches this next: `NavigationBar.selectedIndex` is non-nullable, so the shell renders nothing at all when the route belongs to no destination rather than showing an unhighlighted bar; `AppNavigationRail` must set its own width, because as a `Row` child it would otherwise receive unbounded constraints and claim infinite width; the library section strip needs a `Material` ancestor (a plain `Container` is not enough for `ChoiceChip`), and it only has one now that the wide layout no longer wraps the screen in a `Scaffold`; and `setState(() => field = future)` returns a Future from the callback, which Flutter rejects at runtime — the refresh path uses a block body.

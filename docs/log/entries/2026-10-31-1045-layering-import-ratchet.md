# [2026-10-31 10:45] Add a layering import ratchet for feature architecture rules

- Scope: Start issue #232 by turning AGENTS.md's prose layering rules into a machine-checked ratchet instead of relying on manual counts. A new architecture contract test scans every Dart file under `lib/features/` (224 files today), resolves relative and `package:lyric_forge_ktv/` imports to canonical paths, and enforces four rules: domain must not import `dart:io`/`dart:ffi`/`package:flutter/*`; domain must not import the data or presentation layers; presentation must not import data implementations; data must not import the presentation layer. The ratchet is bidirectional: a new violation fails until the import is fixed, and a fixed violation fails until its stale baseline entry is deleted, so the baseline can only shrink. The other two rules are currently clean and are enforced with empty baselines. AGENTS.md gained one line pointing future work at the ratchet. No production code changed; the violation burn-down itself (abstracting the resolver/linker's file access behind a domain interface, decoupling the six presentation files) is deliberately left as follow-up sub-tasks so each refactor can be reviewed with its own tests.

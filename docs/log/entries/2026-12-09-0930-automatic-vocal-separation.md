# [2026-12-09 09:30] Separate the lead vocal before lyric recognition

- Scope: round 22. The user reported that recognition is still poor on every axis (wrong characters and homophones, missing chorus repeats, soft lines and harmonies, invented lyrics in intros, interludes and outros, bad line breaks and timing) for Mandarin, English, French and Japanese songs, and chose automatic vocal separation as this round's fix, for Windows with an NVIDIA GPU (release target RTX 5080). Changes (D-043):
  - Native separator (`native/vocal_separator`, C++20):
    - `lyricforge-separator --model --input --output-dir [--provider auto|dml|cpu] [--threads] [--vocals-index] [--max-seconds] [--no-accompaniment]`: reads a 44.1 kHz mono or stereo PCM WAV, writes `vocals.wav` and `accompaniment.wav` (mix minus vocals) as 16-bit stereo, atomically, under UTF-8 paths (`wmain` on Windows);
    - line protocol on stdout (`LF_STAGE`, `LF_PROVIDER`, `LF_FALLBACK`, `LF_PROGRESS`, `LF_STATS`, `LF_DONE`, `LF_ERROR`) and exit codes 0/2/3/4/5/6;
    - engine: the vendored demucs.onnx core (`third_party/demucs_onnx`, MIT, pinned revision, patched for a flat ORT include, a static allocator, a fixed seed and no console output) running the htdemucs_ft vocals network on ONNX Runtime; `auto` tries DirectML and falls back to the CPU provider when loading or inference fails;
    - the CLI, WAV and protocol code is a separate library tested with a fake engine (`lfsep_tests`, 18 tests).
  - Model export (`tool/vocal_separator/export_htdemucs_vocals_onnx.py`): picks the bag member that alone produces vocals, exports it at opset 17 with the STFT outside the graph, checks ONNX Runtime against PyTorch (max relative error 1e-3) and writes a sidecar with size, SHA-256, sources and vocals index.
  - Release workflow (`.github/workflows/build-vocal-separator.yml`): Dart contract tests; CLI unit tests on Linux; model export (cached); a Linux CPU build that separates a synthetic 20-second song and checks the stems (`tests/make_test_song.py`, `tests/check_stems.py`); a Windows x64 build against the ONNX Runtime DirectML and DirectML NuGet packages that runs the unit tests, separates into a non-ASCII folder and tries the GPU path; the bundle with `separator-manifest.json` and licences; publication to the `vocal-separator-v1` prerelease outside pull requests. The ASR runtime workflow and release are untouched.
  - App:
    - `ManagedVocalSeparatorRuntime`: fetches the release asset's size and digest, downloads with resume, verifies, extracts to staging, checks the manifest (revision, paths inside the bundle, model size and SHA-256) and `--version`, then swaps the bundle in; concurrent callers share one install; the model hash is remembered against size and modification time.
    - `VocalSeparationPlanner`: off → skip; an imported vocal stem is never replaced; other platforms, missing songs and recordings over 15 minutes skip; an automatic stem is reused while the song file (size, modification time, path) and the separator revision are unchanged.
    - `LocalProjectVocalSeparator`: install, FFmpeg decode to 44.1 kHz stereo, separation into `<project>/stems/run-<time>/`, a vocal stem below 3 % of the mix RMS (about -30 dB) is rejected as "no singing", older unreferenced runs are pruned; every failure becomes an outcome, only cancellation throws.
    - `LocalProjectTranscriptionWorkflow`: an optional separator runs after the start write in a new `separating` phase (cancellable), the stem and its `vocalSeparation` marker are saved under the run's revision, recognition uses the stem, and `metadata.transcription.vocalSeparation` records the outcome; an automatic stem is not trusted when separation is off or fails. Separation progress joins the progress stream as `preprocessing`.
    - `TranscriptionConfig.vocalSeparation` (`automatic` by default, older settings read as automatic), a switch in the recognition settings dialog, diagnostics, and the audio-sources hint no longer claims the app never separates.
    - The end-to-end smoke test workflow is built without a separator.
    - Importing a vocal stem drops the automatic stem's marker, so the imported stem is treated as the user's from then on.

- Notes:
  - The bundle is about 200 MB (float32 model plus ONNX Runtime and DirectML), more than the 80 MB estimated before the work; the setting's description says so.
  - DirectML on the RTX 5080 is not exercised by CI (runners have no GPU); the CPU fallback is. The first real run on the target machine should check `metadata.transcription.vocalSeparation.provider`.
  - The `vocal-separator-v1` release appears only after the workflow runs on main; until then separation fails at install and recognition uses the mix.
  - The automatic stem is also what proofreading and the editor's audition use, since they read `vocalPath`.

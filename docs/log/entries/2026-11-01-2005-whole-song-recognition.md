# [2026-11-01 20:05] Recognise songs whole, keep chunk metadata, invalidate stale checkpoints

- Scope: Phase 1 items 1.1, 1.3 and 1.4 of the recognition-quality roadmap. They all live in the same wrapper, so they shipped together. The wrapper used to cut every song longer than three minutes into overlapping chunks before the engines ever saw it. That contradicted `docs/high_quality_asr.md`, which promises the whole song is sent once, and it produced the seam half-lines, the per-chunk decoder reset and the doubled inference cost that the review attributed to R1. The default chunk threshold is now 20 minutes, which no song reaches, so a song goes to the engine intact and the wrapper only earns its keep for concert-length or audiobook-length audio. Merging those chunks also stopped destroying evidence: the merge used to return a document whose metadata was a single `mergeStrategy` key, throwing away the engine identity, the quality mode and every review candidate. It now rebuilds metadata across chunks, remapping line-indexed fields through the dedup and the final sort, so "use the other engine's line" still works on long audio and the project records the real backend instead of falling back to `local-asr`. Finally the checkpoint manifest only fingerprinted the source file, so changing the mode, engine order or model and pressing "recognise again" silently replayed the previous run's lyrics; the manifest is now version 2 and carries a hash of every result-affecting setting.

- Notes: Raising the threshold rather than deleting the wrapper is a deliberate trade: deleting it would also delete resume, and the defect was never "a wrapper exists", it was "the wrapper's threshold is shorter than a song". Both modes still share the wrapper, which is now the correct behaviour rather than a hazard. Two things were fixed opportunistically because they sat in the same code path: per-chunk working directories (each holding a normalised copy of the audio) are now deleted once the checkpoint is written, and review-candidate `startMs`/`endMs` are shifted into song time. Bumping the manifest version invalidates every existing checkpoint once, which is the point: those checkpoints predate the config fingerprint, so reusing them would repeat the bug. No real-song measurements are claimed here; this is a routing and bookkeeping change, and the acceptance evidence is the tests above.

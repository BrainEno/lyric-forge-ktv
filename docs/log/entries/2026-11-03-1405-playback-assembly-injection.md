# [2026-11-03 14:05] Inject the playback surfaces and delete the unreachable KTV view

- Scope: Phase 4.2, second step — the player feature. Two things were tangled together in `player_screen.dart`: a screen that read seven services straight out of the app-wide locator, and a fullscreen KTV view nobody could reach anymore. Deleting the unreachable view removed four of those seven lookups and about a thousand lines; the surviving screen, Now Playing, the app-shell lyric sync widget and the fullscreen KTV view now take their services as constructor arguments built in `lib/app/`.
- Files: `lib/features/player/domain/services/playback_lyrics_availability.dart` (`PlaybackLyricsResolver` — binds the four collaborators of `resolveAndSyncPlaybackLyrics` once), `lib/features/player/presentation/playback_screen_dependencies.dart` (new: `PlayerScreenDependencies`, `NowPlayingDependencies`), `lib/app/playback_assembly.dart` (new: `buildPlaybackLyricsResolver`, `assemblePlayerScreenDependencies`, `assembleNowPlayingDependencies`), `lib/app/app_services.dart` (`isInitialized`, so the shell can be built before bootstrap), `lib/app/app.dart` (builds the sync widget from the services it was given; skips it before bootstrap), `lib/app/app_router.dart` (routes Now Playing and the player screen with assembled dependencies), `lib/features/player/presentation/screens/player_screen.dart` (2,630 → 1,533 lines), `lib/features/player/presentation/screens/now_playing_screen.dart`, `lib/features/player/presentation/screens/immersive_ktv_screen.dart` (five required services, no per-field locator fallback), `lib/features/player/presentation/widgets/playback_lyrics_availability_sync.dart`, `lib/features/player/presentation/widgets/now_playing_lyrics_project_action.dart`, `test/features/player/playback_lyrics_availability_test.dart` (bundle case + widget wiring), `test/features/player/ktv_take_operation_lock_test.dart` (dropped the source-scan case that asserted on unreachable code), `test/architecture/app_assembly_contract_test.dart` (ratchet lowered to 54 calls / 29 files; playback-surface and single-KTV-owner assertions), `docs/reviews/2026-10-31-recognition-quality-and-ux-deep-review.md`, `docs/log/entries/2026-11-03-1405-playback-assembly-injection.md`, `docs/handoff.md`, `docs/work_log.md`, `docs/work_log_archive.md`, `docs/work_log_index.md`.

- Notes: The deletion is the interesting part. `_FullScreenKtvView`, `_FullScreenKtvViewState`, `_KtvAudioControlsSheet`, `_CompactSourceMenu`, `_FullscreenLyric` and `_FullscreenNoLyrics` were reachable from nothing: the immersive KTV screen replaced them and nothing ever constructed the old view again. Two tests were keeping the corpse warm — the KTV take-lock contract asserted that `player_screen.dart` guards history mutations, and it passed because the guards were in the unreachable widget. **That means the KTV take/record/export UI currently has no entry point at all**: `KtvRecordingService`, `KtvMicrophoneService` and `KtvTakeHistoryStore` are constructed and tested but no screen uses them. Restoring that surface is a product decision, not a refactor, so it is not done here; the assertion that everything still works was removed rather than left pointing at dead code, and the gap is recorded in the review document. Second decision: `PlaybackLyricsResolver` exists instead of four more constructor parameters because the same quartet (repository, metadata repository, session, canonicalizer) is needed by three surfaces, and passing them separately is how the nullable-fallback pattern grew in the first place. Third: `AppServices.isInitialized` was added so `ElysiumPlayerApp` can render its shell in tests before bootstrap without touching a `late final` service — the app shell is otherwise unchanged.

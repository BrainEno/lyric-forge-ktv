# [2026-12-17 09:30] One-click proofreading with online lyrics

- Scope: round 30. The user asked for a review of 歌词校对 (which of the 22 menu entries are useful, marginal or need work) and for proofreading that gives the most accurate lyrics with the fewest steps: when online, fetch the published lyric automatically instead of asking the user to find and paste it, and proofread without manual work. Review result: every correction flow needed a dialog, and the most accurate one (参考歌词) needed a lyric pasted by hand; the text tools (clean-up, loops, repetition, timeline) were safe enough to run together but had to be opened one by one. Changes (D-052):
  - New domain package `lib/features/lyrics/domain/online/`: `OnlineLyricQuery` (title/artist/duration from the project name, stripping extensions, track numbers, brackets, feat., reading "artist - title"), `OnlineLyricSearchService` (all sources in parallel, per-source timeout and failure reason, de-duplication), `OnlineLyricSanitizer` (credit rows such as 作词 : X / Producer: X, the "title - artist" header row, instrumental notices), `OnlineLyricMatcher` (aligns each candidate with the draft in the draft's Chinese script; accepted only when ≥ 50 % of the draft's sung characters and ≥ 35 % of the lyric rows match and both have ≥ 2 rows; title/artist/duration only break ties; timed lyrics get one median shift onto the recording, or lose their timestamps when the shift does not fit).
  - New data sources `lib/features/lyrics/data/services/online_lyrics/`: LRCLIB (`/api/search` by fields, then free text), NetEase (`cloudsearch/pc`, covers redirected to the original song id, then `song/lyric`), Kugou (`krcs` search with the audio duration, then `lyrics.kugou.com/download`, Base64). All addresses in `OnlineLyricEndpoints`; `IoOnlineLyricHttp` uses the model-download proxy settings (falls back to a direct connection).
  - `OneClickProofreadUseCase`: text clean-up defaults → strong recognition-loop fixes → with an accepted lyric, the reference alignment's safe batch (confident replacements and missed rows with a safe slot; manual edits protected; the recording's own timing kept; missed rows dropped first if they would break the timeline, the whole lyric if it still would) and rows spelt exactly like the lyric marked as trusted → without a lyric, default repetition unifications → confident timeline repairs. Counts what it changed and what stayed uncertain; records the lyric's source in `metadata.oneClickProofread`.
  - `AutoProofreadService` + `LyricAutoProofreadFlow`: search, ask only when no lyric matched (edit title/artist and search again, paste a lyric, or apply the offline clean-up), apply once as one undoable change with a summary, then offer the line-by-line review of the uncertain rows with the fetched lyric already filled in. Offline: offline steps only, with the reason.
  - UI: 一键校对 is the first menu entry and a filled button next to 校对 on wide layouts (校对中… while a pass runs). `LyricEditorDependencies.onlineLyricSearch` is assembled in `lyric_editor_assembly.dart`. The coordinator's `openReferenceAlignment` is split so a lyric at hand can be reviewed without the paste dialog; 统一简繁字形 moved from the screen to the coordinator to keep the screen under its size budget.

# [2026-11-02 01:35] Cut the editor toolbar down to its daily controls

- Scope: Phase 3 item 3.2 (review §4.3 and §4.5). The lyric editor's control strip offered about twenty-five controls at once — four read-only metrics, four filter chips, play, insert, the proofreading entry, two toggles, a player link, four offset controls, a progress bar — and on narrow widths the whole band became a horizontal scroll with no scrollbar, so everything past the first few controls was unreachable rather than merely crowded. The complaint that started this review ("有点复杂") is a discoverability failure, not an aesthetic one. Nothing here removes a capability: every control that left the strip is still one press away, and each one landed somewhere a user would look for it.
- Files: `lib/features/lyrics/presentation/widgets/lyric_editor_toolbar.dart` (new: the toolbar, the app-bar overflow menu, and `LyricReviewFilter`, all testable without the editor's services), `lib/features/lyrics/presentation/screens/lyric_editor_screen.dart` (uses the extracted widgets; the duplicated filter enum, the four metric pills, the offset buttons and a stray brace from the move are gone — about 340 lines lighter), `test/features/lyrics/presentation/widgets/lyric_editor_toolbar_test.dart` (new, 7 cases), `docs/reviews/2026-10-31-recognition-quality-and-ux-deep-review.md` (§4.3, §4.5, plan table), `docs/log/entries/2026-11-02-0135-editor-toolbar-reorg.md`, `docs/handoff.md`, `docs/work_log.md`, `docs/work_log_archive.md`.

It also covers the filter menu keeping every count and explanation, the offset button reporting its current value and stepping by 100 ms, "reset to zero" being disabled at zero, the loop toggle appearing only under smart review, and the overflow menu keeping "insert at playback" visible-but-disabled so the user learns why instead of wondering where it went.
- Notes: Two design choices are worth carrying forward. First, the read-only metrics became text (`12 行 · ZH · 待复核 3 · 低置信度 2`) instead of four pills: they were never pressable, so they only competed for the eye. Second, unavailable actions are now disabled with a reason rather than hidden — the old narrow layout silently dropped "在播放位置插入" whenever the project had not been auditioned, which is the same failure mode as the scroll-off-screen buttons. The review's suggested "下一处问题" button does not exist anywhere in the current code, so it was not invented here; it is a new feature, not a rearrangement. Tooling note: two probe iterations were lost to the workflow itself — a step whose last command was a `grep` with no matches fails the step, and diagnostics taken from the *end* of a `flutter test` log show the summary line instead of the assertion, so the probe now greps `Expected:`/`Actual:` and the `[E]` lines directly.

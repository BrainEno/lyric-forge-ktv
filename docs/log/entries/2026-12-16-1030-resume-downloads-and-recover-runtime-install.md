- Scope: round 29, second and third requests. (1) Preparing 最高质量双引擎 stopped with 「识别引擎安装包缺少运行时清单，已保留现有 runtime」 at 99%. A temporary Windows probe downloaded the `asr-runtime-v3` Windows asset: size and SHA-256 match the release, the 14 entries include `runtime-manifest.json` (stored **last**), and both PowerShell 5.1 `Expand-Archive` and `tar.exe` extract it completely on a clean runner. So the asset is fine; on the user's machine the single `Expand-Archive` run must have stopped before the last entry while still exiting 0 (the user's small Whisper zip extracted fine with the same command). The installer trusted the exit code, then had no diagnostics beyond "missing manifest", and a retry fetched the 1.2 GB bundle again because a promoted archive was never reused. (2) The user asked that a download failing mid-way resume from the break point instead of starting over. `ResumableFileDownload` already resumed `.part` files across attempts, but: a dropped connection was not retried in place; a Hugging Face failure deleted the HF part before falling back to ModelScope, which started from zero; the next attempt always began on Hugging Face again and ignored the ModelScope part; verified runtime / FFmpeg archives on disk were downloaded again. Changes (D-051):
  - New `ZipBundleExtractor` + `ZipCentralDirectory`: reads the archive's own file list (classic and ZIP64 end records, Windows separators, zip-slip guard), checks free space against the listed sizes, then tries Windows `tar.exe` → .NET `ZipFile.ExtractToDirectory` → `Expand-Archive` (non-Windows: `unzip` → `tar`), emptying the staging directory before each, and accepts the first output in which every listed file exists with its listed size. PowerShell runs with `-ExecutionPolicy Bypass`, `$ErrorActionPreference='Stop'`, silent progress and a pinned Windows PowerShell module path (a PowerShell 7 parent leaks its own). Every attempt's exit code, stderr and missing files go into the error details. Used by the managed runtime/FFmpeg installer, the standalone Whisper runtime and the vocal separator; no other code runs archive tools.
  - Runtime bundle: a `downloads/asr-runtime.zip` with the release size and SHA-256 is installed without downloading (`已找到上次下载并校验通过的识别引擎安装包，跳过下载`); a stale one is deleted first. The download now passes the release size as `expectedBytes`. A missing manifest reports whether the archive itself lacks it (release problem) or the extraction lost it (disk space / antivirus), with the staging listing; the verified archive is kept so a retry does not re-download. FFmpeg likewise reuses a verified `ffmpeg.zip`.
  - `ResumableFileDownload` gained `transientRetries` / `retryDelay` / `onRetry`: a dropped connection, timeout or short body is retried in place with `Range: bytes=<kept>-`; only failures that add no bytes count against the limit (3 in a row in every installer, cap 64 per fetch); HTTP errors and inconsistent resumes still go to the caller. The progress line says `… 网络中断，已保留 X / Y，N 秒后从断点继续下载（第 n 次重连）`.
  - Qwen model files: on a Hugging Face failure with matching ModelScope metadata the HF part is kept, and moved to the ModelScope part when both publish the same SHA-256 and size and it is longer (`Hugging Face 下载中断，已保留 X，将通过官方 ModelScope 备用源从断点继续`); with different metadata it is still deleted. Before downloading, a longer `.modelscope.part` with the same digest makes the attempt continue on ModelScope. The final SHA-256 check still guards every promoted file.
  - `LocalAsrStoragePreflightService.readAvailableBytes` is now a public static, reused by the extractor's free-space check.
